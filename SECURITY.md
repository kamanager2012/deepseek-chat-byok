# Security Policy & Android Release Signing Guide

DeepSeek Chat BYOK is a local-first, MIT-licensed client. User API keys remain strictly on-device and are sent only to the endpoint configured by the user.

## 1. BYOK Key & Data Isolation

- **Storage**: Provider configurations and API keys are stored solely in browser `localStorage` (`chat-demo:providers-v1`, `chat-demo:api-key`). Conversation trees, attachments, and Memory Cards are stored in IndexedDB (`chat-demo`).
- **Backups, Non-Destructive Merge & Emergency Recovery**:
  - ZIP archives generated by `exportArchive` (`manifest.json`, `sessions/...`, `index.json`, and images) omit settings, provider presets, and `user.json`.
  - Markdown exports contain only visible conversation text.
  - `commitStaging('merge')` defaults to `conflictPolicy: 'keep-existing'`, strictly preserving existing local conversations and newer local turns whenever an imported backup shares a session `id`. Users must explicitly opt into `keep-both` (new generated ID copy) or `overwrite` inside `ImportDialog` when conflicts are detected.
  - `exportEmergencyBackup()` verifies per-session readability against `sessionSummaries`, refuses to claim complete backup if any session is missing or unreadable (surfacing partial recovery counts and skipped IDs instead, or failing if 0 of >0 sessions are readable).
- **CI → Pages / Release Supply-Chain Gate**:
  - `main` branch protection requires passing pull request checks (`verify`, `android-apk`). Both GitHub Pages deployment (`pages.yml`) and Release publication (`release.yml`) verify that `verify`, `android-apk`, and `android-release-upgrade` completed with `success` on the exact commit SHA before deploying or publishing assets.
- **Error Redaction**: `redactApiSecrets()` in `src/services/api/client.ts` redacts `Bearer <token>` and `sk-*` credentials from HTTP, network, and stream error messages before displaying or persisting error state.

## 2. Proxy & Android WebView Security Controls

Both local forwarding layers (`server.mjs` for Node/Desktop/LAN and `LocalBridgeServer.java` for Android) enforce:

- **Method & Header Filtering**: Allows only `GET`, `POST`, `DELETE`, `HEAD` (plus canonical loopback CORS `OPTIONS` preflight when Android falls back from port `18787`); forwards only `authorization`, `x-api-key`, `anthropic-beta`, `anthropic-version`, `content-type`, and `accept`; strips `Cookie`, `Host`, `Origin`, `Referer`, `Set-Cookie`, and proxy headers.
- **CSRF, Canonical Origin & DNS-Rebinding Defense**:
  - Rejects `Origin: null`, cross-origin `Origin`/`Referer`, and cross-site `Sec-Fetch-Site`.
  - Enforces loopback-only `Host` (`127.0.0.1`, `localhost`, `[::1]`) when bound to loopback (Node `restrictLoopbackHost` and Android `LocalBridgeServer`).
  - Android `MainActivity` locks the WebView origin to canonical `http://127.0.0.1:18787` by serving bundled assets in-process via `shouldInterceptRequest`, preventing origin drift across port conflicts while keeping `127.0.0.1:18787` IndexedDB/`localStorage` continuity across upgrades. If port `18787` is occupied, `/_proxy` seamlessly binds a fallback loopback port exposed via `AndroidExportBridge.getProxyUrl()`.
  - Android `MainActivity` generates a 256-bit `SecureRandom` per-launch `bridgeToken` exposed via `AndroidExportBridge.getBridgeToken()`. `client.ts` attaches `X-DS-Bridge-Token` exclusively on local `/_proxy` calls (never to remote API URLs and never forwarded upstream), preventing unrelated Android apps from invoking `/_proxy?url=...`.
- **SSRF, DNS Pinning & Payload Limits**:
  - Both `server.mjs` and Android `LocalBridgeServer` pin the validated DNS-resolved IP address directly onto the upstream TCP/TLS socket (`SNIHostName` + strict `HTTPS` endpoint identification on Java `SSLSocket`), eliminating DNS-rebinding TOCTOU windows.
  - Remote targets require `https://` without embedded URL credentials (`user:pass@`).
  - Blocks loopback, RFC 1918, CGNAT (`100.64.0.0/10`), link-local / cloud metadata (`169.254.0.0/16`, `fe80::/10`), ULA (`fc00::/7`), NAT64 (`64:ff9b::/96`), deprecated site-local (`fec0::/10`), and multicast ranges. Loopback targets (`127.0.0.1`/`localhost`) are permitted only from loopback clients for local Ollama usage, with self-proxy recursion blocked.
  - Blocks `3xx` upstream redirects (`502`).
  - Enforces `25 MB` request body cap (`413`) and a bounded proxy worker pool (`MAX_WORKERS = 32`, `503` on saturation) on Android.
- **WebView, Crash & Markdown Isolation**:
  - Markdown raw HTML renders as escaped text nodes; links allow only `http:`, `https:`, and `mailto:`; Mermaid runs with `securityLevel: 'strict'`; KaTeX keeps `trust: false`.
  - React wraps `<App />` in a top-level `ErrorBoundary` allowing redacted diagnostics and direct IndexedDB emergency ZIP backup if a rendering error occurs.
  - Android `MainActivity` sets `android:allowBackup="false"`, restricts cleartext HTTP in `network_security_config.xml` strictly to `127.0.0.1` and `localhost`, opens only `http:`/`https:`/`mailto:` links externally, recovers from WebView `onRenderProcessGone` / load errors cleanly, and caps SAF chunked exports (`MAX_EXPORT_SESSIONS = 4`, `MAX_EXPORT_BYTES = 256 MiB`) with error surface via `Toast`.
- **Known Residual Risks**:
  - **Shared GitHub Pages Origin (`kamanager2012.github.io`)**: Project-path GitHub Pages (`https://kamanager2012.github.io/deepseek-chat-byok/`) shares a single Web Origin (`https://kamanager2012.github.io`) — and therefore shares `localStorage` and IndexedDB isolation boundaries — with sibling repositories published under the same GitHub account (`ai-infra-hegemony`, `chengyu-storybook`, `dsh-community`, `pose-notes`). For strict origin isolation of browser API keys and chat history on public Web/PWA deployments, deploy `dist/` onto a dedicated subdomain (`CNAME`) or an isolated host (e.g. Cloudflare Pages `*.pages.dev`), or run the signed **Android Release APK** (`http://127.0.0.1:18787`) / **Portable Desktop (`server.mjs`)** build.
  - Provider API keys remain stored in client-side `localStorage` (`chat-demo:providers-v1`) on Web/PWA and inside Android WebView app storage rather than hardware enclave / Android Keystore (protected on Android by private app sandbox, `allowBackup="false"`, `allowFileAccess="false"`, and XSS/Markdown sanitization).
  - `--host 0.0.0.0` (`scripts/start-lan.sh`) exposes the server on LAN without TLS; terminate HTTPS via a reverse proxy (e.g., Caddy, Nginx, Tailscale Serve) outside trusted loopback environments.

## 3. Android Release Keystore Setup (Formal Upgrade Path)

Release APKs signed across builds with the same keystore support in-place upgrades without uninstalling prior versions. **Never commit `.jks` or `.keystore` files** (ignored via `.gitignore`).

1. **Generate a release keystore locally** (store safely offline in a password manager / vault):

   ```sh
   keytool -genkeypair -v \
     -keystore deepseek-chat-byok-release.jks \
     -alias deepseek-byok \
     -keyalg RSA -keysize 2048 -validity 10950
   ```

2. **Encode to Base64 for GitHub Actions** and delete temporary base64 text files afterward:

   ```sh
   base64 -w 0 deepseek-chat-byok-release.jks
   ```

3. **Configure GitHub Repository Secrets** (`Settings -> Secrets and variables -> Actions`):
   - `DS_KEYSTORE_BASE64`: single-line Base64 string of the `.jks` file
   - `DS_KEYSTORE_PASSWORD`: keystore password
   - `DS_KEY_ALIAS`: e.g., `deepseek-byok`
   - `DS_KEY_PASSWORD`: key password

4. **Verify future release APKs**:

   ```sh
   sha256sum -c SHA256SUMS.txt
   apksigner verify --verbose --print-certs deepseek-chat-byok-v*-android-release.apk
   ```

## 4. Official Android Release Signing Certificate Fingerprint

Starting with `v0.2.2+`, official Android release APKs (`*-android-release.apk`) are signed with a persistent release certificate so users can upgrade in place without losing local chat history, Memory Cards, or API keys:

- **Signer DN**: `CN=DeepSeek Chat BYOK Release, OU=Community, O=DeepSeek Chat BYOK, L=NA, ST=NA, C=US`
- **Algorithm**: RSA 2048 (`SHA256withRSA`, APK Signature Scheme v2)
- **Certificate SHA-256 Digest**: `86:D8:29:E2:15:71:AF:ED:FC:AE:69:0F:24:0A:DA:7F:33:8E:4C:10:FD:99:97:DD:C7:A1:8A:E9:DA:91:AD:A7`
- **Certificate SHA-1 Digest**: `8E:19:DF:09:86:4D:2D:86:8E:B8:75:91:A5:2C:DA:95:99:64:05:91`

> Prior debug releases (`v0.2.0`, `v0.2.1`) used ephemeral CI debug certificates and cannot be upgraded in place into the signed release channel without backing up and uninstalling first.
